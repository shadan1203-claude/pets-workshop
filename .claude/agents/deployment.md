# Deployment Pipeline

## Deployment Status

The repository now has a GitHub Actions validation and build pipeline at [.github/workflows/deployment.yml](../.github/workflows/deployment.yml).

An external hosting target, deployment command, environment name, credentials, and approval policy are `Not Found` in the available requirements and repository source. The workflow therefore validates and builds the application but does not publish it to an external environment.

## Pipeline Triggers

- Pull request events run the validation and build jobs.
- Pushes to `main` run the validation and build jobs.
- `workflow_dispatch` supports an explicitly initiated run.

The exact production branch and release trigger are not established beyond the workflow configuration above.

## Pipeline Jobs

### Documentation sync

Runs the repository-native validator:

```text
python -m documentation_sync validate --manifest .github/documentation-sync-manifest.json --format json
```

This checks manifest scope, source discovery, evidence provenance, status values, missing-evidence policy, and source consistency.

### Backend tests

The job installs `app/server/requirements.txt` and runs the existing Flask `unittest` suite from `app/server`.

### Frontend build

The job uses the committed `app/client/package-lock.json`, runs `npm ci`, executes `npm run build`, and uploads `app/client/dist` as a build artifact named with the commit SHA.

### Frontend E2E tests

The job installs backend and frontend dependencies, installs Chromium with Playwright, and runs:

```text
npm run test:e2e -- --project=chromium
```

The existing Playwright configuration starts the Flask test server and Astro development server.

### Deployment boundary

The final job depends on all validation and build jobs. It reports successful completion and explicitly records that the deployment target is `Not Found`. It performs no external write.

## Security Controls

- Workflow permissions are limited to `contents: read`.
- No deployment credentials or external service tokens are configured.
- Dependency installation uses committed lockfile data for the frontend.
- Documentation sync remains restricted by `.github/documentation-sync-manifest.json`.
- Concurrency cancels superseded runs for the same workflow and ref.
- Application source code is not modified by the pipeline.

## Release and Promotion

No deployment or promotion command is defined because the repository does not establish a hosting provider, deployment platform, environment topology, or approval workflow. Adding deployment requires clarification of:

1. Target platform and resource/application identifier.
2. Environment names and promotion order.
3. Required credentials and secret storage.
4. Branch, tag, or manual approval policy.
5. Rollback and health-check behavior.
6. Artifact retention and release traceability requirements.

Until those decisions are supplied, the workflow's successful endpoint is a validated build artifact rather than a deployed environment.

## Local Reproduction

From the repository root:

```text
python -m documentation_sync validate --manifest .github/documentation-sync-manifest.json --format json

Push-Location app/server
python -m unittest -v test_app.py
Pop-Location

Push-Location app/client
npm ci
npm run build
npm run test:e2e -- --project=chromium
Pop-Location
```
